## Overview

The Finance Head Dashboard is a comprehensive module designed for Finance Heads (userRoleId = 20) to manage and approve payroll batches generated by the HR department. This module provides:

- **Dashboard Summary Metrics**: Real-time overview of pending payrolls, budget requirements, and processed employees
- **Payroll Process Table**: Paginated, filterable table displaying all payroll batches with status tracking
- **Detailed Payroll View**: Modal displaying itemized employee payroll breakdown with deductions and allowances
- **Approval Workflow**: Approve or reject payroll batches with remarks/reasons
- **Export Functionality**: Download payroll reports in Excel or PDF format

### Key Design Principles

✅ **Role-Based Access Control**: Only users with `userRoleId = 20` can access this module  
✅ **Positional Parameters**: All FETCH actions use positional parameters (no DTO wrappers)  
✅ **Consistent UI**: Matches Accounting module styling and layout patterns  
✅ **Redux Standards**: Follows project's Redux architecture with consolidated imports

## Features

### 1. Dashboard Summary Cards

Four metric cards displaying key information:

| Card | Description | Icon | Color |
|------|-------------|------|-------|
| **Pending Payrolls** | Total number of payroll batches awaiting approval | Clock | Yellow |
| **Total Budget Required** | Sum of all pending payroll amounts | DollarSign | Blue |
| **Employees Processed** | Total employees in pending payrolls | Users | Purple |
| **Approved Amount** | Total approved payroll amount this month | CheckCircle | Green |

### 2. Payroll Process Table

**Columns:**
- **Batch ID**: Unique identifier for the payroll batch
- **Period / Description**: Payroll period with school year
- **Department**: Department or "All" for company-wide
- **Employees**: Total number of employees in batch (badge format)
- **Total Amount**: Total payroll amount (PHP currency format)
- **Status**: Pending/Approved/Rejected (color-coded badges)
- **Created Date**: Batch creation date
- **Actions**: View, Approve, Reject, Export buttons

**Features:**
- ✅ Server-side pagination (10, 25, 50, 100 rows per page)
- ✅ Search functionality (batch ID, period, department)
- ✅ Status filtering (Pending, Approved, Rejected, All)
- ✅ Responsive design with horizontal scrolling
- ✅ Row hover effects
- ✅ Conditional action buttons (approve/reject only for pending)

### 3. Payroll Details Modal

**Summary Section:**
- Total Employees
- Total Basic Salary
- Total Allowances
- Total Deductions
- Total Net Pay (prominent display)

**Employee Breakdown Table:**
- Employee Name & Number
- Department & Position
- Basic Salary
- Allowances (green with trending up icon)
- Deductions (red with trending down icon)
- Net Pay (bold, highlighted)

**Export Options:**
- Export to Excel (.xlsx)
- Export to PDF (.pdf)

### 4. Approval/Rejection Workflow

**Approval:**
- Confirmation dialog with batch details
- Optional remarks field
- Immediate status update
- Toast notification on success

**Rejection:**
- Mandatory reason field (validation enforced)

### Action Creators (Positional Parameters)

#### FETCH Actions

```javascript
// Dashboard Summary (No parameters)
fetchFinanceDashboardSummary()
  → GET /finance/dashboard-summary
  → Returns: { ok, data: { totalPendingPayrolls, totalBudgetRequired, ... } }

// Payroll Process Table (Positional parameters - NO DTO wrapper)
fetchPayrollProcessTable(page = 1, pageSize = 10, search = '', status = '')
  → GET /finance/payroll-process-table?page=1&pageSize=10&search=&status=
  → Returns: { ok, data: [...], totalRecords: number }

// Payroll Batch Details
fetchPayrollBatchDetails(batchId, page = 1, pageSize = 50)
  → GET /finance/payroll-batch-details/{batchId}?page=1&pageSize=50
  → Returns: { ok, data: { summary: {...}, employees: [...] } }
```

#### MUTATION Actions

```javascript
// Approve Payroll (Payload object - OK per standards)
approvePayrollBatch(payload)
  → POST /finance/approve-payroll-batch
  → Body: { batchId, remarks }
  → Returns: { ok, message }

// Reject Payroll (Payload object - OK per standards)
rejectPayrollBatch(payload)
  → POST /finance/reject-payroll-batch
  → Body: { batchId, reason }
  → Returns: { ok, message }

// Export Report (Payload object - OK per standards)
exportPayrollReport(payload)
  → POST /finance/export-payroll-report
  → Body: { batchId, format: 'excel' | 'pdf' }
  → Returns: { ok, message, fileUrl } or blob download
```

## Route Protection

### Access Control Implementation

**Route Definition:**
```javascript
// In AppRoutes.jsx
<Route
  path="/finance/dashboard"
  element={
    <ProtectedRoutes allowedRoles={[20]}>
      <FinanceDashboard />
    </ProtectedRoutes>
  }
/>
```

### How It Works

1. **User Login**: User logs in and receives JWT token with `userRoleId` in payload
2. **Route Access**: User navigates to `/finance/dashboard`
3. **Protection Check**: `ProtectedRoutes` component checks if `userRoleId === 20`
4. **Authorization**:
   - ✅ **Granted**: User has `userRoleId = 20` → Dashboard loads
   - ❌ **Denied**: User has different role → Redirected to `/accessdenied`

### Access Denied Page

**Location:** `src/components/SharedComponents/AccessDenied.jsx`

**Features:**
- School-themed illustration (book with lock and graduation cap)
- Clear error message

## User Guide

### For Finance Head Users

#### 1. Accessing the Dashboard

1. Log in with Finance Head credentials (userRoleId = 20)
2. Navigate to `/finance/dashboard` via sidebar menu
3. Dashboard loads with summary metrics and payroll table

#### 2. Reviewing Payroll Batches

**View Pending Payrolls:**
- Click "Pending" tab to filter pending payrolls
- Use search box to find specific batches by ID, period, or department
- Review batch details: employees count, total amount, created date

**View Details:**
1. Click "View" button on any payroll batch
2. Modal opens showing:
   - Summary cards (employees, salary, allowances, deductions)
   - Net pay total (prominent display)
   - Employee breakdown table with individual payroll items
3. Scroll through employee list (paginated)
4. Export report if needed (Excel/PDF)
5. Close modal when done

#### 3. Approving Payroll Batches

1. Locate pending payroll batch in table
2. Click "Approve" button (green)
3. Review batch details in confirmation dialog
4. Optionally add approval remarks
5. Click "Approve Payroll" to confirm
6. Success toast appears
7. Table refreshes with updated status

#### 4. Rejecting Payroll Batches

1. Locate pending payroll batch in table
2. Click "Reject" button (red)
3. Review batch details in rejection dialog
4. **Enter rejection reason** (mandatory)
5. Click "Reject Payroll" to confirm
6. Success toast appears
7. Table refreshes with updated status

#### 5. Exporting Reports

**From Table:**
- Click export icon (FileDown) on any payroll batch
- Report downloads as Excel file automatically

**From Details Modal:**
- Open payroll details modal
- Click "Export Excel" or "Export PDF" button
- Report downloads with batch details and employee breakdown

#### 6. Filtering and Searching

**Status Filters:**
- **Pending**: Shows only unapproved payrolls
- **Approved**: Shows approved payrolls
- **Rejected**: Shows rejected payrolls
- **All**: Shows all payrolls regardless of status

**Search:**
- Enter keywords: batch ID, period name, department
- Table updates in real-time
- Pagination resets to page 1 on search

## Backend Requirements

### Database Schema

**Suggested Tables:**

```sql
-- Payroll Batch Master Table
CREATE TABLE PayrollBatch (
    BatchId INT PRIMARY KEY IDENTITY(1,1),
    PeriodDescription NVARCHAR(200) NOT NULL,
    SchoolYear NVARCHAR(50) NOT NULL,
    Department NVARCHAR(100),
    TotalEmployees INT NOT NULL,
    TotalAmount DECIMAL(18,2) NOT NULL,
    Status NVARCHAR(20) NOT NULL, -- 'Pending', 'Approved', 'Rejected'
    CreatedDate DATETIME NOT NULL DEFAULT GETDATE(),
    CreatedBy NVARCHAR(100) NOT NULL,
    ApprovedDate DATETIME NULL,
    ApprovedBy NVARCHAR(100) NULL,
    ApprovalRemarks NVARCHAR(500) NULL,
    RejectedDate DATETIME NULL,
    RejectedBy NVARCHAR(100) NULL,
    RejectionReason NVARCHAR(500) NULL
);

-- Payroll Batch Details (Employee Line Items)
CREATE TABLE PayrollBatchDetails (
    DetailId INT PRIMARY KEY IDENTITY(1,1),
    BatchId INT FOREIGN KEY REFERENCES PayrollBatch(BatchId),
    EmployeeId INT NOT NULL,
    EmployeeName NVARCHAR(200) NOT NULL,
    EmployeeNumber NVARCHAR(50) NOT NULL,
    Department NVARCHAR(100) NOT NULL,
    Position NVARCHAR(100) NOT NULL,
    BasicSalary DECIMAL(18,2) NOT NULL,
    TotalAllowances DECIMAL(18,2) NOT NULL DEFAULT 0,
    TotalDeductions DECIMAL(18,2) NOT NULL DEFAULT 0,
    NetPay DECIMAL(18,2) NOT NULL
);
```

### Controller Implementation (C# Example)

```csharp
[ApiController]
[Route("api/finance")]
[Authorize] // Requires authentication
public class FinanceController : ControllerBase
{
    [HttpGet("dashboard-summary")]
    [Authorize(Roles = "FinanceHead")] // Role-based authorization
    public async Task<IActionResult> GetDashboardSummary()
    {
        // Implementation
        var summary = await _financeService.GetDashboardSummaryAsync();
        return Ok(new { ok = true, data = summary });
    }

    [HttpGet("payroll-process-table")]
    [Authorize(Roles = "FinanceHead")]
    public async Task<IActionResult> GetPayrollProcessTable(
        [FromQuery] int page = 1,
        [FromQuery] int pageSize = 10,
        [FromQuery] string search = "",
        [FromQuery] string status = "")
    {
        // Implementation with pagination
        var result = await _financeService.GetPayrollTableAsync(
            page, pageSize, search, status);
        return Ok(new { 
            ok = true, 
            data = result.Data, 
            totalRecords = result.TotalRecords 
        });
    }

    [HttpPost("approve-payroll-batch")]
    [Authorize(Roles = "FinanceHead")]
    public async Task<IActionResult> ApprovePayrollBatch(
        [FromBody] ApprovePayrollRequest request)
    {
        // Validate request
        if (request.BatchId <= 0)
            return BadRequest(new { ok = false, message = "Invalid batch ID" });

        // Update batch status
        await _financeService.ApprovePayrollAsync(
            request.BatchId, 
            User.Identity.Name, 
            request.Remarks);

        return Ok(new { 
            ok = true, 
            message = $"Payroll batch #{request.BatchId} approved successfully" 
        });
    }

    // Similar implementations for other endpoints...
}
```

### Business Logic Considerations

1. **Status Transitions**:
   - Pending → Approved (allowed)
   - Pending → Rejected (allowed)
   - Approved → Rejected (not allowed without special permission)
   - Rejected → Approved (requires re-review workflow)

2. **Audit Trail**:
   - Log all approval/rejection actions
   - Store user ID, timestamp, and remarks/reasons
   - Maintain history for compliance

3. **Notifications**:
   - Notify HR when payroll is approved/rejected
   - Notify Finance Head when new payroll batch is submitted
   - Email notifications for critical actions

4. **Data Integrity**:
   - Validate batch totals match employee line items
   - Ensure no duplicate batches for same period
   - Lock batch after approval to prevent modifications

## Troubleshooting

### Common Issues

**Issue:** Finance Dashboard shows blank page  
**Solution:** Check browser console for errors. Verify Redux store includes `finance` reducer.

**Issue:** "Access Denied" when userRoleId = 20  
**Solution:** Check JWT token payload. Ensure `userRoleId` field is present and equals 20.

**Issue:** Table shows "No payroll batches found"  
**Solution:** Verify backend endpoint is reachable. Check network tab for API response.

**Issue:** Approve/Reject button doesn't work  
**Solution:** Check backend endpoint implementation. Verify request payload structure.

**Issue:** Export downloads empty file  
**Solution:** Check backend file generation logic. Verify blob/file URL is valid.
